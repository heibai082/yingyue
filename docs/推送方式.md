# 推送方式（自用）

平时直接 `git push origin main`。**国内直连 github.com 经常被重置**，这时有两个备选：

## 1. 重试（大多数情况够用）

```powershell
cd D:\dev\sakura-read
git -c http.proxy= -c https.proxy= push origin HEAD:main
```

今天实测 11 次里成 1～2 次，脚本化重试（每次间隔 60 秒）通常几分钟内能推上去。

## 2. 走 NAS 的网络（这招是通的）

本机连不上、重试也不行时，用 NAS（杭州）的出口——NAS 能直连 GitHub，
SSH 的 TCP 转发被禁用了，但 NAS 上的容器里有 git：

```powershell
& "C:\Users\bqche\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" `
  "D:\文档\deepseek-harness\default-workspace\sakura-patch\push_via_nas.py"
```

脚本做的事：

1. 本机 `git bundle create` 把 `main` 打包
2. SFTP 传到 NAS → `docker cp` 进容器 `sqmusic-lite`（alpine，git 2.45）
3. 容器里 `git fetch` bundle → 用 Windows 凭据管理器里的 token push 到 GitHub
4. 用 GitHub API 核对 `origin/main` 的 sha 是否等于本机 HEAD
5. 清理 NAS 与容器里的临时文件

参数（可选）：`push_via_nas.py <repo_dir> <local_branch> <remote_branch>`，
默认 `D:\dev\sakura-read` / `main` / `main`。
