## A. 已核实的 bug / 功能缺口

| # | 问题 | 证据 | 影响 | 建议优先级 |
|---|---|---|---|---|
| A1 | **在线书的阅读进度条拖不动**：`_jumpToProgress` 在 `totalChars <= 0` 时直接 return，而在线的章节从未写 `charCount`（只有 TXT/EPUB 导入时才写），所以在线书 `totalChars == 0` | `reader_page.dart:1838`；`book_store.dart:613/656` 是唯一写 charCount 的地方 | 拖动进度条无反应（在线小说）；漫画走漫画页不受影响 | P1 |
| A2 | **漫画「张加载失败（长按重试）」是空承诺**：只画了文案，没有任何 `onLongPress` 处理 | `comic_reader_page.dart:504`（全文无 onLongPress） | 用户长按没反应，只能退出重进 | P2 |
| A3 | **移除书籍不清理其缓存**：`clearBookCache` 只有详情页「清除缓存」会调；`removeById` 只删源文件 | `book_store.dart:753` 唯一调用点 `book_detail_page.dart:216` | 长期使用后 `files/books/` 里堆孤儿目录（漫画可能几 GB），只能整机清 | P1（存储） |
| A4 | **设置里「清除缓存」会清掉下载好的正文**：它删的是 `chapterCacheRoot`（现在是持久目录，等于用户下载的章节）；而且标签还写着「EPUB 章节缓存」 | `settings_page.dart:1157`；`book_store.dart:47`（root=files/books） | 点一下等于清空所有离线书；名字没提醒 | P1（UX 风险） |
| A5 | **广告 URL 规则过宽**：`looksLikeAdUrl` 里有 `contains('/app/')`，若某站图片路径含 `/app/` 会把整章图片全部过滤掉 | `ad_page_filter.dart:239` | 极端情况下「这一话没取到图片」 | P2 |
| A6 | **宽横幅判定可能误删跨页彩图**：`ratio <= 0.55` 一律当广告，个别跨页大图会被删（有「最多删一半」兜底，但会少一页） | `ad_page_filter.dart` `_looksLikeAd` | 少一页，不影响整章 | P3 |
| A7 | **半缓存的漫画章节算「已缓存」**：只要图片目录里有 ≥1 张就算命中，规划时会跳过它 | `book_store.dart` `hasCachedChapter` | 断网看这一话缺图 | P2 |
| A8 | **图片地址一变，缓存就「失联」**：图片按 URL 命名，站点换 CDN / 换签名后旧文件还在但匹配不上，`已缓存` 会掉回 0（正文不受影响） | `comic_image_cache.dart` `comicImageKey(url)` | 换源/站点轮换后会重新下载一次 | P2（有取舍） |
| A9 | **追更迁移的位移只搜 0~120**：老缓存按序号命名，若一本书在缓存后新增超过 120 话，位移猜不中 → 那本不迁移（不会错，但会重下） | `book_store.dart` `_guessShift` | 极端情况重下 | P3 |
| A10 | `comicCachedCount` / `BookCachePlan.covers` 是死代码 | `comic_image_cache.dart:228`；`models.dart` | 无功能影响，维护噪音 | P3 |

## B. 性能 / 稳定性隐患

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| B1 | **缓存扫描是 O(N) 同步 IO**：`refreshChapterCache` 对每章做文件 stat，漫画还要 `listSync` 图片目录；1187 章实测 ~100ms（PC，手机更慢） | 实测（见提交记录外的基准）：`refresh 1187 章（300 话有图）≈106ms` | 详情页打开、开始缓存时可能掉帧 |
| B2 | **漫画图片下载没有上限、没有并发**：逐张 `await`，一批 17 张；按章 4 并发 | `comic_image_cache.dart` `cacheComicImages` | 整本漫画下载慢；「暂停」要等当前章图片下完 |
| B3 | **批量缓存没有磁盘余量检查**（reader-go 有，这里没有） | `offline_downloader.dart` | 可能把手机写满 |
| B4 | **没有缓存容量上限 / 自动清理**（LRU、按时间、按书） | 全局无实现 | 长期使用无限增长 |
| B5 | **188 处 `catch (_) {}`**：迁移、缓存写入失败都被静默吞掉 | 全库统计 | 出问题时没日志、难排查 |
| B6 | 启动即后台追更（延迟 15s 串行跑所有书），无 Wi-Fi 限制、无并发上限 | `home_page.dart` `_runCacheTrack` | 流量/耗电；书多时启动后几分钟都在后台跑 |
| B7 | `migrateLegacyCaches` 每次启动都会跑（有 legacy 目录才动手，但仍要 stat） | `book_store.dart` | 可忽略，但建议一次性标记 |

## C. 建议升级（按性价比）

**先修（低风险、收益直接）**
1. A1 在线书进度条：`totalChars == 0` 时按「章数 + 阅读顺序」跳转（不依赖字数）。
2. A3/A4：移除书时可选「同时删缓存」；设置里把「清除缓存」拆成「清章节缓存（保留下载）」和「清全部下载」。
3. A2：给失败的图加真正的长按重试（或改成「点一下重试」）。
4. A5：`/app/` 改成更精确的 `app-download` / `download-app`，并加「若过滤后为空则不过滤」兜底。

**存储治理**
5. 缓存容量上限（如 2GB）+ 按最久未读自动清理；详情页显示「本书缓存占用」（`bookCacheBytes` 已存在但没接 UI）。
6. B3：缓存前检查剩余空间，<1GB 暂停并提示。

**体验**
7. 「仅 Wi-Fi 下载/追更」开关；后台追更限速/并发 2。
8. 漫画图片下载并发 2~3 + 支持取消到「下一张」粒度（B2）。
9. 半缓存章节（A7）区分「完整/部分」，部分缓存的章在断网时给「缺图」提示。

**体积与依赖**
10. APK 60MB → 字体（13MB）与内置 TTS 模型（17.8MB）做成「按需下载」，预计可降到 ~30MB。
11. `sherpa_onnx` 升 2.0.3（TTS API 有变，需回归语音）；`xml` 升 7.x（EPUB 解析需回归）；`cupertino_icons` 升 2.0.0。
12. Kotlin 2.4.10 → ≥2.4.20（构建时有官方弃用警告）。

**工程**
13. `reader_page.dart` 4234 行拆分（分页 / 滚动流 / 工具栏 / TTS 各一文件）。
14. 加 GitHub Actions 跑 `flutter test`（现在只有本地跑）。
15. 把 188 处静默 catch 里「值得知道的」改成 `debugPrint`（至少迁移、缓存写入）。

## D. 建议的下一步

先只做 A1 + A3 + A4 + A2（都是小改动、可回归测），再把「缓存容量上限 + 余量检查」当成一个独立版本。
本锚点（`anchor-0.46`）保持不动，后续每条都开分支验证，失败可随时回到这个 tag。
